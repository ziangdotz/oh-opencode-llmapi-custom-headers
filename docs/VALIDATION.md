# 验证范围

目标：OpenCode 2.3.2，插件 v0.1.1，配置版本 1。

工程交付规范更新：发布门禁 `npm run verify:release` 通过，包含 22 项逻辑测试、无 Solid 上下文的原生编辑器检查、类型/格式检查及包清单检查。新增回归验证损坏存储不写入、迁移拒绝数组、已保存但同步失败的提示、新增向导保留并发的其他路由修改。Zod 升级到 4.6.7 后，隔离真实宿主三协议 HTTP 回归通过。CI 执行相同门禁、生产审计及超时检查，远端结果以当前提交的 Actions 记录为准。生产依赖审计已清零；开发 picomatch 的本地防护和残留版本告警详见 DEPENDENCY-REVIEW.md。纯生产安装包在工作区外安装后也通过真实宿主三协议回归。

配置简化更新：移除路由/模型名称和共享集成属性，旧存储加载迁移；新提交严格拒绝已移除字段。新增逐模型输入类型选择，JSON 编辑直接从路由列表打开，统一 models 在 headers 前。17 项更新后的逻辑测试覆盖迁移、独立集成、输入类型、顺序、返回和密钥提示。隔离真实 2.3.2 终端确认直接 JSON 编辑、新增模型类型选择、请求头和保存流程。下文的分项菜单等描述是此前验证记录，已由此流程取代。

2026-11-18 真实终端回归：通过命令行伪终端启动隔离的 OpenCode 2.3.2 `--standalone`，先复现用户的 `buffer.length` 崩溃。堆栈定位到 RGBA 克隆：旧代码将 `ctx.theme.text` 颜色集合当作颜色传入。现使用 `ctx.theme.surface("dialog")` 下的嵌套颜色字段，补齐 `@opencode/theme` 类型依赖，测试主题也改为相同结构。

修复后已在该真实终端完成：新增测试路由、粘贴两个模型 ID、粘贴请求头 JSON、Ctrl+S 保存、重新打开模型列表、打开高级路由 JSON、无效 JSON 显示校验错误、返回后恢复无效草稿，以及从编辑器逐级返回分项菜单、路由列表、主菜单和会话界面。未再出现截图中的崩溃；仅使用隔离测试数据，没有修改日常路由或发送模型请求。该回归只覆盖本机 Windows / OpenCode 2.3.2，不等于所有终端和平台已验收。

此前 `No renderer found` 已通过改用 SDK `ctx.renderer` 和原生 Renderable 处理；无 Solid 根/上下文的渲染检查继续覆盖编辑、返回与监听释放。TUI 入口静态导入编辑器，使宿主加载阶段可追踪完整 UI 依赖。

逐级返回更新：17 项逻辑测试覆盖编辑器 → 分项菜单 → 路由列表 → 主菜单、草稿恢复、连续保存使用最新 revision、新增向导上一步与草稿保留；原生渲染检查覆盖可点击返回入口及草稿变更回调。

多行输入更新：13 项逻辑测试、格式及类型检查通过。使用 Bun 1.4.3 与 OpenTUI 0.8.4 无头原生渲染验证多行粘贴、Enter、Tab、Ctrl+A、Ctrl+S、校验失败保留草稿、终端高度变化及弹窗关闭取消；分项模型编辑验证既有模型能力和推理参数保留。可复跑命令为 `npm run test:tui`。此项为原生组件测试，未替代真实 OpenCode 终端交互验收。

2026-11-18 升级验证：SDK 精确固定为 2.3.2，格式检查、类型检查及 10 项测试通过（含 TUI 管理逻辑）。在隔离的本地 OpenCode 2.3.2 服务上，通过真实插件 RPC 读取/保存配置、刷新目录，并捕获三协议请求路径及自定义请求头；端点返回预期 HTTP 400。此次未重新进行真实终端 UI 交互、真实密钥连接或完整流式响应验收。下文 2.3.0 的实测记录为历史基线。

已验证的功能基线：配置与请求头校验、大小写无关合并、保存冲突/持久化失败、模型目录解析与合并、TUI 取消/删除确认、集成关联与终端缓存同步。真实宿主确认三个 exports 可识别；TUI 单命令已验证，用户已确认配置和连接成功。隔离测试确认 API key 通过 OpenCode 保存并在 Session 请求中形成 Authorization。三协议本地 HTTP 测试确认请求路径及自定义头；模拟端点返回预期 HTTP 400，不等于完整流式响应验收。
