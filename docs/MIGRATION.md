# 迁移

本文说明从旧 DSH 配置或早期插件配置迁移到当前 `0.1.0` / schema `1` 的边界。迁移在加载配置时执行，保存时使用严格 schema。

## 1. 迁移原则

- **保留可映射字段**：协议、Base URL、请求头、模型 ID、上下文/输出限制和输入能力。
- **移除已废弃字段**：显示名称、共享集成引用和模型名称。
- **拒绝无等价映射的字段**：旧默认 reasoning、重试、流式空闲超时、图片压缩/像素限制和 Anthropic reasoning 映射。
- **不静默导入**：未知字段会导致保存失败，而不是被忽略。
- **凭据不迁移**：旧环境变量或共享集成中的密钥不会自动复制或删除。

## 2. 加载时移除的字段

旧记录中的以下字段会在加载时移除：

| 位置 | 字段          | 说明                                    |
| ---- | ------------- | --------------------------------------- |
| 路由 | `displayName` | 路由只使用 ID 展示                      |
| 路由 | `credential`  | 每条路由使用独立集成 `llmapi-<路由 ID>` |
| 模型 | `name`        | 模型只使用 ID 展示                      |

迁移后，旧的 `credential` 引用不会自动转换为新集成。原来使用共享集成的路由，需要在其独立集成中重新配置密钥：

```text
/connect → LLM API Custom Headers · <路由 ID> → API key
```

旧共享集成的密钥不会被插件复制或删除；需要时由使用者在 `/connect` 中单独处理。

## 3. 保留的字段

| 旧字段          | 新字段             | 说明                           |
| --------------- | ------------------ | ------------------------------ |
| 协议            | `api`              | 三种协议保持不变               |
| Base URL        | `baseURL`          | 必须是绝对 http(s) 地址        |
| 请求头          | `headers`          | 字符串到字符串；大小写无关合并 |
| 模型 ID         | `models[].id`      | 必填，同一路由内唯一           |
| 上下文窗口      | `contextWindow`    | 默认 `262144`                  |
| 最大输出        | `maxTokens`        | 默认 `32768`                   |
| 输入能力        | `models[].input`   | `text` / `image`，至少一项     |
| OpenAI 推理映射 | `reasoningEfforts` | 非 Anthropic 路由支持          |

配置版本保持 `1`，storage key 保持 `configuration`，路由 ID 和 Provider 前缀保持稳定。

## 4. 明确拒绝的字段

以下旧设置没有等价映射，保存时会被拒绝：

| 旧设置                               | 原因                                         |
| ------------------------------------ | -------------------------------------------- |
| 旧默认 reasoning 配置                | 新模型使用显式 `reasoningEfforts` 或宿主默认 |
| `retryPolicy`                        | 重试由宿主管理，插件不提供旧语义             |
| `streamIdleTimeoutMs`                | 流式超时由宿主管理                           |
| 图片最大字节数 / 像素限制 / 压缩配置 | 媒体处理由宿主管理                           |
| Anthropic `reasoningEfforts`         | 需要 thinking budget，当前无等价映射         |

如果旧配置包含这些字段，迁移会失败并指名字段。请删除或转换为新字段，不要通过关闭校验绕过。

## 5. 迁移步骤

1. 停止 OpenCode。
2. 备份配置目录、数据目录和旧插件目录。
3. 记录旧插件版本、配置 schema 和路由列表。
4. 安装当前插件 `0.1.0`，保持配置 schema `1`。
5. 启动宿主，加载旧记录；插件会移除可迁移的废弃字段。
6. 打开 `/llmapi-custom-headers`，核对每条路由的协议、Base URL、请求头和模型。
7. 对每条路由执行 `/connect`，配置独立 API key。
8. 使用“发现模型”或手工编辑补齐模型能力；发现不会删除已有模型。
9. 保存后检查 `/models` 中的 `llmapi-<路由 ID>`。
10. 按 [验证](VALIDATION.md) 做无模型检查。

## 6. 迁移后的差异

| 项目     | 旧行为                 | 当前行为                               |
| -------- | ---------------------- | -------------------------------------- |
| 路由显示 | 可使用显示名称         | 只显示路由 ID                          |
| 模型显示 | 可使用模型名称         | 只显示模型 ID                          |
| 凭据     | 可能共享集成或环境变量 | 每条路由独立集成，通过 `/connect` 保存 |
| 请求头   | 可能按对象展开合并     | 大小写无关合并，路由值优先             |
| 模型发现 | 可能覆盖目录           | 按 ID 合并，保留已有设置               |
| 保存     | 可能无 revision 检查   | revision 冲突检测 + 串行写入           |
| 远端访问 | 可能启动时拉取目录     | 只有显式“发现模型”访问远端             |

## 7. 回滚

1. 停止宿主。
2. 恢复旧插件目录和旧配置/数据快照。
3. 重启宿主。
4. 核对旧路由和凭据引用。

迁移会移除废弃字段。如果新版本已保存，旧版本可能无法理解新结构；回滚应使用迁移前备份，而不是只替换代码。

## 8. 常见问题

### 迁移后 `/connect` 没有路由

确认配置已保存并执行主菜单“刷新”。每条路由的集成 ID 为 `llmapi-<路由 ID>`；如果路由 ID 变更，集成也会变化。

### 旧密钥还能用吗

插件不会复制或删除旧共享集成的密钥。需要在新的独立集成中重新保存。删除路由也不会删除已保存凭据。

### 为什么保存时提示未知字段

新 schema 是严格的。按错误信息删除旧字段；不要修改数据库或关闭校验。

### 为什么 Anthropic 推理配置被拒绝

Anthropic 需要 thinking budget，当前插件没有等价映射。先移除该字段；后续版本若支持，会提供显式迁移说明。
