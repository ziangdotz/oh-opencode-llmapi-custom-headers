# 安全模型

本文描述插件的信任边界、资产、威胁和现有控制。它不是第三方安全审计，也不构成生产安全认证。

## 1. 资产

| 资产           | 位置                    | 敏感性 |
| -------------- | ----------------------- | ------ |
| API key        | OpenCode 凭据系统       | 高     |
| 自定义请求头   | 插件配置 / 宿主 storage | 可能高 |
| 路由和模型配置 | 插件配置 / 宿主 storage | 中     |
| 远端端点地址   | 插件配置                | 中     |
| 宿主日志       | OpenCode 日志目录       | 可能高 |

插件不保存明文密钥。`resolveKey` 只从集成活动连接解析 `key` 类型凭据，并在请求时使用。

## 2. 信任边界

```text
可信：OpenCode 宿主、宿主凭据系统、插件源码、插件配置
部分可信：用户配置的 LLM 端点、网关、代理
不可信：网络响应、远端模型目录内容、日志查看者、工单附件
```

插件假设：

- 配置由可信操作者维护。
- 宿主正确实现凭据存储和插件隔离。
- 端点由操作者选择；插件不判断端点是否可信。
- 网络响应可能恶意、超大、格式错误或试图触发重定向。

## 3. 威胁与控制

### 3.1 凭据泄露

威胁：

- 密钥写入配置、日志、错误消息或仓库。
- 请求头中混入密钥并被导出。
- 问题报告附带完整认证头。

控制：

- 密钥只存在宿主凭据系统。
- 插件只持有集成 ID。
- 错误消息不回显密钥值。
- 文档和模板要求脱敏。
- 发布包不包含本机配置、数据库或日志。

残余风险：

- 用户可能把密钥写进自定义请求头。
- 宿主日志可能由其他组件记录请求头。
- 备份可能包含敏感配置。

### 3.2 SSRF 与内网访问

威胁：

- 恶意配置让发现请求访问内网、元数据服务或本机端口。
- 通过重定向绕过目标限制。

控制：

- 只接受绝对 `http` / `https` 地址。
- 发现请求使用 `redirect: "error"`，不跟随重定向。
- 30 秒超时和 4 MiB 响应体上限。
- 远端访问只在用户显式执行“发现模型”时发生。

非目标：

- 不阻止 localhost、内网、链路本地地址或云元数据地址。
- 不提供 DNS 固定、IP 允许列表或网络隔离。
- 不支持多租户隔离。

因此，插件只适合由可信操作者配置端点。不要在多租户环境中让不可信用户控制 Base URL。

### 3.3 请求头注入

威胁：

- 通过请求头值注入 CRLF 或非法字段。
- 通过大小写重复字段制造歧义。
- 覆盖自动鉴权头导致凭据被替换。

控制：

- 使用 Fetch 的 `Headers` 构造器校验字段名和值。
- 拒绝 `Content-Length`、`Transfer-Encoding`、`Expect`、`Upgrade`。
- 合并按小写字段名进行，每个字段只保留一个值。
- 路由请求头优先，这是显式设计；操作者应知道它可以覆盖自动鉴权。

残余风险：

- 有权限修改配置的人可以改变请求头。
- 某些网关对重复字段或大小写有特殊行为；插件通过单字段合并降低歧义。

### 3.4 恶意或异常响应

威胁：

- 超大响应导致内存耗尽。
- 非 JSON 或异常结构导致解析错误。
- 慢响应占用连接。

控制：

- 先检查 `Content-Length`，再累计实际字节。
- 超过 4 MiB 立即拒绝并取消 body。
- 30 秒超时；调用方信号可提前取消。
- 只接受 `data` 数组或 `models` 对象，其他形状报错。
- 跳过无 ID 条目，避免单行异常导致目录整体失败。

### 3.5 配置篡改与冲突

威胁：

- 并发写入覆盖其他编辑。
- 损坏记录导致插件以空配置启动。
- 未知字段被静默忽略。

控制：

- revision 冲突检测。
- 写入队列串行化。
- 加载时严格校验；损坏记录拒绝加载，不用空配置覆盖。
- 新保存严格 schema，未知字段报错。
- 写入成功后才推进内存 revision。

限制：

- 只覆盖单插件实例，不提供跨进程事务。
- 多实例同时写同一 storage 的行为由宿主决定。

### 3.6 供应链

威胁：

- 依赖被替换或引入漏洞。
- 开发工具被恶意输入触发灾难性回溯。
- 宿主模块与插件副本不一致。

控制：

- 使用 `npm ci` 和 lockfile。
- 生产依赖只有 Zod。
- SDK、主题和 OpenTUI 由宿主运行时提供。
- 开发依赖使用精确版本和 overrides。
- 对已知 picomatch 问题添加本地防护和回归。
- CI 对生产依赖告警阻断。

限制：

- 本地防护不冒充上游修复。
- 没有第三方供应链审计或签名验证。
- 发布包未签名。

### 3.7 日志与诊断泄露

威胁：

- 诊断时上传完整配置、密钥或内部地址。
- 日志包含请求头。

控制：

- 文档要求脱敏。
- 错误消息不包含密钥。
- 发布包不包含日志或数据库。

操作者仍需在提交工单前人工检查附件。

## 4. 安全默认值

- 没有后台轮询或遥测。
- 只有显式发现访问远端。
- 发现拒绝重定向。
- 请求头合并去重。
- 配置严格校验。
- 密钥不落盘到插件配置。

## 5. 非目标

- 不提供 SSRF 防护边界。
- 不提供多租户隔离。
- 不提供密钥轮换、审计日志或合规证明。
- 不提供请求签名、mTLS 或代理。
- 不保证第三方端点的安全性。
- 不提供 SLA、灾难恢复保证或生产认证。

## 6. 报告漏洞

如发现漏洞：

1. 不要在公开 issue 中披露可利用细节、密钥或内部地址。
2. 通过维护者提供的私下渠道报告；当前仓库尚未配置专用安全邮箱。
3. 提供插件版本、宿主版本、复现步骤、影响和脱敏证据。
4. 优先针对 `v0.1.0` + OpenCode `2.4.2` 复现。

维护者应在修复前限制传播，修复后更新 CHANGELOG 和验证记录。

## 7. 发布前安全检查

```sh
npm audit --omit=dev
npm run verify:release
```

确认：

- 没有密钥、个人路径、数据库或日志进入发布包。
- 依赖审计结果已记录。
- 文档中的示例是占位值。
- 未验证的安全相关功能已明确标注。
