# 运行与交付规范

当前兼容基线为插件 0.1.1、配置版本 1、OpenCode 2.3.2。开发使用 Node.js 22+，原生 TUI 检查使用 Bun 1.4.3；宿主直接加载 TypeScript 源码。

## 发布门禁

从干净 checkout 执行 `npm ci` 和 `npm run verify:release`。该命令包含格式、类型、逻辑、原生渲染及包清单检查。随后执行 `npm pack`，记录安装包 SHA-256、提交 ID、宿主版本和回归结果。真实宿主测试使用隔离目录与测试密钥；禁止对日常服务运行会替换配置的 test:host。

Windows/Linux CI 执行相同门禁，产物只有通过门禁后才能上传。CI 配置已提供不等于远端运行通过。发布前还需真实 2.3.2 终端确认打开 JSON、输入类型、校验、保存、返回及 /connect 关联；HTTP 抓包的预期 400 只能证明路径和请求头。

## 配置与数据

OpenCode plugin storage 的 configuration 记录优先于初始 options。每条路由独立关联 llmapi-路由ID；密钥由 OpenCode 保存。显示名称及共享集成旧字段仅在加载时迁移，下一次保存才写回新结构。原共享集成的密钥不会自动复制，需通过 /connect 重新配置。

升级前保留旧安装包，并在 OpenCode 停止后备份其数据目录；路径通过宿主 debug paths 确认。路由 JSON 导出可能包含敏感请求头，备份不得上传仓库。回滚同时考虑插件包与配置快照，不能假设换回代码就能恢复已移除的字段。配置损坏时停止写入，先保留原始记录，再从备份恢复；插件不会以空配置静默覆盖损坏数据。

## 故障恢复

| 现象                   | 处理                                                 |
| ---------------------- | ---------------------------------------------------- |
| 保存冲突               | 返回路由列表重新打开，核对后再提交，避免覆盖其他编辑 |
| 已保存但刷新或同步失败 | 使用 Refresh / 刷新；不要将它当作写入失败重复新增    |
| 新增过程中 ID 被占用   | 返回 ID 步骤选择其他值，已有草稿保留                 |
| 密钥无效               | /connect 中检查路由独立集成及活动 API key            |
| 配置校验失败           | 修复指定字段；不要删除数据库规避错误                 |
| 编辑器崩溃             | 记录宿主版本、复现步骤和脱敏报错，保留原配置         |

## 支持边界

写入串行化及 revision 检测限于一个插件实例，未提供跨进程分布式锁。模型发现只读一页，限制 4 MiB 和 30 秒；手动刷新不会访问远端目录。没有后台轮询或遥测上传。端点允许本机和内网，必须由可信操作者配置。

当前没有独立安全审计、SLA、完整多协议流式验收或 WebSocket 实连验收。插件生产依赖安全审计为零，CI 对新增生产告警阻断；SDK 和 UI 工具仅作开发依赖，运行时使用宿主模块。开发 picomatch 的本地防护与残留版本告警见 DEPENDENCY-REVIEW.md。工程门禁和测试记录应作为交付证据，不替代外部审计或宿主安全验收。
